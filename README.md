# Proprietary files for the Redmi Pad (yunluo)

Vendor blobs and firmware images that the LineageOS 24.0 build for the
Redmi Pad (`yunluo`, MediaTek MT6789) needs alongside
[android_device_xiaomi_yunluo](https://github.com/damnms/android_device_xiaomi_yunluo).

## Origin

- **Blobs:** imported from
  [xiaomi-mt6789-devs/android_vendor_xiaomi_yunluo](https://github.com/xiaomi-mt6789-devs/android_vendor_xiaomi_yunluo)
  at commit `a2cff06ecff89e9b97cbbcb24ec6a9fe6d241967`. According to
  `proprietary-files.txt` in the device tree they come from
  `missi_pad_global-user 14 UP1A.231005.007 V816.0.9.0.ULYMIXM`.
- **Firmware (`radio/`):** according to `proprietary-firmware.txt` in the
  device tree, taken from the `V816.0.7.0.ULYMIXM` fastboot package.
  `Android.mk` checks each image against its SHA-1.

## Firmware in the OTA package

`BoardConfigVendor.mk` adds every image in `radio/` to
`AB_OTA_PARTITIONS`. Installing the LineageOS zip therefore also writes
`preloader_raw`, `lk`, `tee`, `gz`, `scp`, `sspm`, `mcupm`, `spmfw`,
`dpm`, `pi_img`, `dtbo` and `logo` to the inactive slot.

## Changes against the imported blobs

- Drop `hardware/lineage/compat` from the Soong namespace imports.
- Rename the `libformatter` prebuilt to `libformatter_mtk` (stem kept as
  `libformatter`) to avoid a clash with the platform module.
- Drop the prebuilt `vendor.mediatek.hardware.bluetooth.audio@2.1/@2.2`,
  `vendor.mediatek.hardware.netdagent@1.0` and `wlan_assistant` in
  favour of the open-source versions from `hardware/mediatek`.
- Link the MTK blobs that use tinyxml2 against `libtinyxml2-v10`
  (patchelf 0.17.2), matching the `blob_fixups` in the device tree's
  `extract-files.py`. The platform tinyxml2 is no longer ABI-compatible
  with these blobs.

## Regenerating

The files in this repository are generated by the scripts in the device
tree. Do not edit `Android.bp`, `Android.mk`, `BoardConfigVendor.mk` or
`yunluo-vendor.mk` by hand.

```bash
cd device/xiaomi/yunluo
./extract-files.py <path to a stock dump>
./setup-makefiles.py
```

`extract-files.py` applies the `blob_fixups`; `setup-makefiles.py`
only regenerates the makefiles from `proprietary-files.txt`.
